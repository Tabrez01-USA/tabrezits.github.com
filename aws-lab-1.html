Cloud Computing • Lab #1

AWS Infrastructure Setup

Objective: Provision a isolated Virtual Private Cloud (VPC) and deploy a public-facing EC2 instance running an Nginx web server.

Incoming Helpdesk Ticket #1042

Client: Vanguard Retail Systems

Priority: Medium

Description: "We need to launch a secure public web application on AWS. It must sit inside its own isolated cloud network with a block size of /16. The server must only accept web traffic on HTTP port 80 and secure shell access on port 22 from our administrator network."

1 Step 1: Provision the VPC Network

Log into your AWS Management Console and navigate to the **VPC Dashboard**.

  • Click Create VPC.
  • Select VPC only.
  • Name Tag: vanguard-prod-vpc
  • IPv4 CIDR block: Enter 10.0.0.0/16 (This creates a massive pool of 65,536 private IP addresses).

2 Step 2: Create a Public Subnet

Now carve out a smaller chunk of your network for the server to live inside.

  • Go to Subnets > click Create Subnet.
  • Select your newly created vanguard-prod-vpc.
  • Subnet Name: vanguard-public-sn-1a
  • IPv4 CIDR block: Enter 10.0.1.0/24 (Provides 256 internal IP addresses for this single zone).

3 Step 3: Attach an Internet Gateway (IGW)

By default, a VPC is entirely cut off from the outside world. To allow clients to load the website, connect an edge gateway.

  • Go to Internet Gateways > Create internet gateway.
  • Name it vanguard-igw and hit create.
  • Select your gateway, click the Actions dropdown, and choose Attach to VPC. Select your VPC.

4 Step 4: Configure Firewall Rules (Security Group)

Let's enforce the precise access requests detailed in the client's support ticket.

  • Go to Security Groups > Create security group.
  • Add an Inbound Rule: Type = HTTP (Port 80), Source = 0.0.0.0/0 (Allows web visitors from anywhere worldwide).
  • Add a second Inbound Rule: Type = SSH (Port 22), Source = Select **My IP** or input the admin range to lock down console commands.

🎉 Verification Checklist

Once you spin up an EC2 instance in this subnet using your security group, visit its public IP address in a clean browser tab. If you see the welcome screen, Ticket #1042 is resolved!
