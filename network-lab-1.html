Network Architecture • Lab #1

Subnetting & Local DHCP Architecture

Objective: Re-engineer a collapsing Class C local area network by implementing logical subnet allocation and resilient DHCP address clustering.

Incoming Helpdesk Ticket #2087

Client: Horizon Logistics Corp

Priority: High / Critical

Description: "Our main distribution center is experiencing massive network drops. We originally deployed a simple flat home-style network using 192.168.1.X. We just scaled up our wireless scanners and warehouse inventory workstations from 30 devices to 180 devices. New devices are failing to get an IP address entirely, and static servers are dropping connections due to IP collisions."

1 Step 1: Calculate the New Subnet Mask (CIDR Conversion)

The client's original network mask was a standard Class C block (255.255.255.0 or /24), which caps out at 254 usable address allocations. Because they have reached 180 devices and are expanding rapidly, they have safely crossed into critical overhead territory.

To give them room to expand to up to 500 total host nodes without rebuilding their structural baseline again, we will shift their mask down to a **Supernet block** (/23).

  • New Network Block: 192.168.0.0/23
  • New Subnet Mask: 255.255.254.0
  • Total Usable Host Pool: 510 unique network addresses spanning from 192.168.0.1 through 192.168.1.254.

2 Step 2: Establish the Topology IP Schema

To stop rogue wireless hardware or workstations from taking over critical infrastructure addresses, we must divide our brand new address pool into strict engineering logical blocks:

Device Allocation Category IP Address Range Scope Purpose / Usage Type
Core Gateways 192.168.0.1 Main Core Router Edge Interface
Managed Switches 192.168.0.2 - 192.168.0.20 Layer 2/3 Backplane Switching hardware
Static Production Servers 192.168.0.21 - 192.168.0.50 Domain Controllers, Local Print Management
DHCP Dynamic Host Scope 192.168.0.51 - 192.168.1.254 Dynamic Range (Scanners, Handhelds, PCs)

3 Step 3: Program the Core DHCP Server Scope

Access your primary network management server or core router console to provision the active pool that fixes Horizon Logistics' address exhaustion crisis.

  • Configure the Address Range Start block to 192.168.0.51 and set the terminal scope to 192.168.1.254.
  • Set the default routing gateway interface destination exactly to 192.168.0.1.
  • Map the primary network DNS pointer to Google’s high-performance public arrays (8.8.8.8) or your localized domain server cluster address.
  • CRITICAL STEP: Change the dynamic reservation lease time limit downward to 4 Hours (instead of the standard 8 Days). Because warehouse scanners drop off and turn on constantly as shifts cycle out, a tight lease duration guarantees that inactive devices release their slots back into the active pool immediately instead of locking them up!

🎉 Network Verification Checklist

Open an elevated command prompt terminal window on an inventory workstation node. Type ipconfig /release followed cleanly by ipconfig /renew. If the host successfully receives a fast allocation mapping above .50 with a mask reading 255.255.254.0, Ticket #2087 is officially closed!
